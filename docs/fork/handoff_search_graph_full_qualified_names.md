# Полный `qualified_name` в строках `search_graph` и `trace_path`

Статус: реализовано и проверено.
Дата: 2026-08-07.
Ветка: `v0.9.1-rc.1-lora`.
База апстрима: `v0.9.1-rc.1`
(`ee9833df2c72b750378273897ffec9410fc2c4f2`).

## Назначение

Сделать каждый `qualified_name` в ответах `search_graph` и `trace_path`
самостоятельным значением. Клиент не должен восстанавливать QN из `qn_prefix`,
точки-разделителя и `qn_suffix`.

## Проявление дефекта

После добавления к C++ QN канонической сигнатуры перегрузки в имени появились
точки, не являющиеся границами пространства имён или символа. Например, поиск
`log_info` в проекте DSP возвращал:

```text
qn_prefix: libs.sniper.log.log.log_info<typename...T0>(const char*,const T0&..
qn_suffix: )
```

Исходный QN был одним значением:

```text
libs.sniper.log.log.log_info<typename...T0>(const char*,const T0&...)
```

`trace_path` использовал ту же операцию `strrchr(qn, '.')` и поэтому ломал QN
с `...` таким же образом. Следовательно, оба ответа не позволяли безопасно
передать точный идентификатор в следующий вызов без эвристического склеивания.

## Причина

Сгруппированный формат `search_graph` экономил повторяющиеся префиксы: группа
содержала `qn_prefix` и путь к файлу, а строка — только `qn_suffix`. В
`trace_path` группа не содержала путь, но восстанавливала QN по тому же правилу.
Разделитель находился через `strrchr(qn, '.')`, то есть последняя точка в полном
тексте QN считалась границей символа.

Это предположение было верно только для прежней формы QN, где точки встречались
в пути и языковых областях. В C++ `...` из пакета параметров шаблона и
вариативных параметров тоже содержит точки.

## Контракт после исправления

- Текстовый `format: "tree"` по умолчанию возвращает плоскую таблицу. Первый
  столбец — полный `qn`, затем `name`, `label`, `file`, `lines`, `in`, `out` и
  запрошенные через `fields` свойства.
- `format: "json"` возвращает тот же плоский контракт:

  ```json
  {
    "total": 2,
    "count": 2,
    "cols": ["qn", "name", "label", "file", "lines", "in", "out"],
    "rows": [["полный qualified_name", "…"]],
    "has_more": false
  }
  ```

- Текстовый `trace_path` возвращает в `callees` и `callers` плоские таблицы:
  первый столбец — полный `qn`, второй — `hop`. Дополнительные `risk` и `args`
  остаются следующими столбцами, когда соответствующие флаги включены.
- `trace_path` в `format: "json"` возвращает для каждой ветви объект с
  `cols` и `rows`; первый столбец `qn` хранит полный идентификатор.

- В обоих форматах отсутствуют `qn_prefix`, `qn_suffix`, `groups` и требование
  склеить части QN.
- `qualified_name` передаётся как непрозрачное строковое значение: любая точка,
  включая точки из `...`, остаётся частью того же идентификатора.
- C++-перегрузки остаются отдельными строками с разными полными QN.
- `detail: "ids"` по-прежнему выдаёт только полный `qn` для широкого
  перечисления.
- Параметры поиска, пагинация, сортировка QN, `fields` и `include_connected`
  сохраняют свои прежние значения.

## Состав исправления

- `src/mcp/mcp.c`: заменить сгруппированный по префиксу вывод `search_graph` плоскими
  строками в текстовом и JSON-формате, так же заменить вывод `trace_path` и
  обновить описания обоих MCP-инструментов.
- `tests/test_mcp.c`: обновить прежние проверки формы ответа и добавить
  регрессионные сценарии с C++ QN с вариативными параметрами для `search_graph`
  и `trace_path`.
- `docs/fork/handoff_search_graph_full_qualified_names.md`: сохранить причину,
  внешний контракт и границы исправления для последующего переноса fork-а.

## Регрессионный сценарий

Тест добавляет в граф в памяти узел `Function` со значением:

```text
libs.sniper.log.log.log_info<typename...T0>(const char*,const T0&...)
```

Он вызывает `search_graph` с `name_pattern: "^log_info$"` и
`fields: ["signature"]` в обычном и JSON-формате. Оба ответа обязаны содержать
исходный QN непрерывной строкой; JSON обязан вернуть `rows`, но не `qn_prefix` и
не `groups`.

До исправления текстовый ответ отсекал QN на последней точке из `...`, а JSON
разносил его по `qn_prefix` и `qn_suffix`.

Отдельный сценарий создаёт CALLS-ребро между двумя C++ QN с вариативными
параметрами и запускает `trace_path` с точным `qualified_name` источника. В
текстовом и JSON-ответе
целевая функция должна присутствовать полным QN без `qn_prefix`, `qn_suffix` и
`groups`.
