# Стабильные `qualified_name` для перегрузок C++

Статус: перенесено на `v0.10.8` и функционально проверено.
Дата текущего переноса: 2026-08-23.
Ветка переноса: `v0.10.8-lora`.
Текущая upstream-база: `v0.10.8`
(`46ae198fc11cda80e817acbc5f5908d7c2de7032`).
Исходная база реализации: `v0.9.1-rc.1`
(`ee9833df2c72b750378273897ffec9410fc2c4f2`).

## Назначение

Сохранять каждую перегрузку вызываемого символа C++ как отдельный узел графа и
использовать существующий `qualified_name` как стабильный идентификатор
конкретной перегрузки. Для обнаружения всех перегрузок использовать уже
существующее короткое поле `name`; отдельное группировочное поле не вводить.

Отдельный `symbol_id` в этой доработке намеренно не вводится: точным
идентификатором, который принимают и возвращают инструменты MCP, служит
канонический `qualified_name`.

## Исправленный дефект

Хранилище графа и буфер графа в памяти считают сочетание
`(project, qualified_name)` уникальным. До этой доработки индексатор C++
формировал одинаковый `qualified_name` для всех перегрузок. Поэтому более
позднее определение перезаписывало или подавляло более ранние. В результате в
поиске оставалась одна произвольно выбранная перегрузка, а её рёбра могли
относиться к другой перегрузке.

## Контракт

### Поля идентичности

Для каждого перегружаемого вызываемого символа C++:

- `name` — короткое имя из исходного кода, например `data`; у перегрузок одного
  символа оно совпадает и используется для их обнаружения;
- `qualified_name` — стабильный канонический идентификатор конкретной
  перегрузки, например:
  - `ns::f(int)`;
  - `ns::f(std::string_view)`;
  - `ns::Buffer::data()`;
  - `ns::Buffer::data() const`;
  - `ns::Worker::run() &`;
  - `ns::Worker::run() &&`.

В примерах показан смысловой C++-суффикс имени. В хранилище сохраняется принятый
в проекте префикс модуля, построенный из относительного пути исходного файла, а
C++-области разделяются точками. После перехода на локальные QN имя проекта
хранится отдельно; сохранённое имя может иметь вид
`path.to.file.ns.Buffer.data() const`.

Перегрузки одного символа имеют одинаковое `name`, но остаются отдельными узлами
с разными `qualified_name`. Совпадение короткого имени может также охватывать
одноимённые символы из разных областей, поэтому оно служит только для
обнаружения кандидатов. Нельзя выбирать перегрузку лишь потому, что она была
обработана первой или последней.

### Каноническая сигнатура C++

Канонический `qualified_name` включает:

- полностью квалифицированное имя вызываемого символа;
- канонизированное представление типов параметров в порядке объявления;
- квалификаторы метода `const` и `volatile`;
- ref-квалификаторы метода `&` и `&&`;
- параметры шаблона;
- связанные ограничения, включая конструкции `requires`.

Имена параметров шаблона нормализуются по их позиции. Поэтому переименование
параметра шаблона не меняет идентификатор. Реализация выполняет синтаксическую
канонизацию: удаляет незначимые пробелы и комментарии и нормализует перечисленные
выше элементы в пределах разобранной единицы трансляции. Сведение псевдонимов,
объявленных через `typedef` или `using`, с исходными типами и другая
семантическая канонизация компилятором не выполняются.

В идентификатор не входят:

- номера строк и столбцов исходного кода;
- имена параметров;
- значения аргументов по умолчанию;
- возвращаемый тип, в том числе тип после `->`;
- `noexcept` и его выражение.

Существующая модель QN добавляет стабильный префикс, вычисленный из
относительного пути файла в репозитории, ко всем символам C++. Поэтому символы
с внутренним связыванием из разных единиц трансляции не сталкиваются. Этот
префикс никогда не зависит от номера строки; перенос символа в другой файл,
напротив, меняет QN и не входит в обещанную этой доработкой стабильность.

### Граф и инкрементальная индексация

- Существующий уникальный ключ `(project, qualified_name)` сохраняется.
- Каждая перегрузка добавляется и обновляется независимо.
- Ссылки и рёбра `CALLS` указывают на разрешённый канонический
  `qualified_name`, а не на произвольный узел с тем же `name`.
- При изменении сигнатуры инкрементальная переиндексация удаляет старый узел.
- При изменении только номеров строк или имени параметра узел и его
  `qualified_name` сохраняются.

### Поведение MCP

`search_graph`:

- возвращает каждую перегрузку отдельным результатом;
- выдаёт `name` и полный канонический `qualified_name` в столбце `qn` плоского
  ответа; сгруппированная форма с `qn_prefix` и `qn_suffix` удалена последующей
  доработкой;
- принимает `name_pattern`; точный шаблон короткого имени, например `^f$`,
  возвращает все найденные перегрузки и одноимённые символы из других областей.

`get_code_snippet`:

- принимает канонический `qualified_name` для точного выбора перегрузки;
- не выбирает перегрузку молча при неоднозначном коротком имени;
- при неоднозначности возвращает канонические имена кандидатов.

`trace_path`:

- принимает канонический `qualified_name` для точного выбора начального узла;
- строит путь только для этой перегрузки;
- не объединяет пути разных перегрузок только из-за совпадения их коротких
  имён;
- при неоднозначном неканоническом запросе возвращает кандидатов.

Поиск через `name_pattern` сохраняется как средство обнаружения символов и
возвращает все подходящие канонические перегрузки.

## Реализация

- Дополнительное поле идентичности не добавляется: `CBMDefinition`, графовый
  буфер, конвейер и SQLite-хранилище используют существующие `name` и
  `qualified_name`. Извлекатель для C++ и CUDA записывает каноническую
  сигнатуру непосредственно в `qualified_name`.
- Общий C++-канонизатор используется при извлечении определений, построении
  областей сырых вызовов и в C/C++ LSP. Он удаляет имена обычных параметров,
  значения по умолчанию, возвращаемый тип и `noexcept`, но сохраняет типы,
  cv/ref-квалификаторы, шаблонные параметры и ограничения.
- Имена шаблонных параметров для идентичности заменяются позиционными именами
  `T0`, `T1`, … без фиксированного ограничения на их количество. Для
  семантического разрешения вызовов отдельно сохраняются исходные имена
  параметров шаблона, поэтому канонизация не ломает вывод типов LSP.
- `namespace` входит в QN согласованно во всех проходах. Благодаря этому
  определение, сырой вызов и LSP используют один и тот же QN для функций и
  методов внутри `namespace`.
- Реестр функций обнаруживает кандидатов через существующий индекс коротких
  имён, затем проверяет область и точный канонический QN. Разрешённый вызов
  возвращает QN конкретной перегрузки, а резервное текстовое разрешение не
  выбирает случайный вариант из набора.
- `search_graph` возвращает `name` и канонический QN и поддерживает поиск через
  `name_pattern`. `get_code_snippet` и `trace_path` принимают точный QN, а для
  неоднозначного короткого имени возвращают кандидатов.
- Инкрементальная переиндексация удаляет узел со старым QN после изменения
  сигнатуры, не затрагивая остальные перегрузки.

## Обязательные регрессионные проверки

Тесты подтверждают следующее:

1. `f(int)` и `f(std::string_view)` образуют разные узлы и результаты поиска.
2. `data()`, `data() const` и `data() volatile` образуют разные узлы и
   результаты поиска.
3. `f() &` и `f() &&` образуют разные узлы и результаты поиска.
4. После вставки несвязанных строк перед символом его канонический
   `qualified_name` не меняется.
5. После переименования параметра канонический `qualified_name` не меняется.
6. Изменение типа параметра меняет `qualified_name`, а инкрементальная
   индексация удаляет устаревший узел.
7. Точные запросы `get_code_snippet` и `trace_path` выбирают только указанную
   перегрузку, а неоднозначные короткие имена возвращают кандидатов.

## Перенос на `v0.10.8`

В upstream `v0.10.8` C++-перегрузки всё ещё не различались каноническими QN,
поэтому исправление перенесено полностью. При слиянии потребовалась адаптация к
новой модели точных вхождений в исходном коде, использующей `source_origin`:

- сопоставление вызовов и ссылок сравнивает текстовый последний сегмент с
  каноническим QN с учётом сигнатуры;
- промежуточное представление деструктора сохраняет текстовое имя `~Type`, а
  семантическая строка — канонический QN `~Type()`;
- точный индекс параллельного прохода строит последний сегмент по короткому
  имени точно найденного графового узла, поэтому ключи `render` и `render()`
  больше не расходятся;
- новые сценарии upstream для повторных вызовов и коллизий координат между
  исходным и препроцессированным текстом сохранены для C++ и CUDA;
- плоские ответы `search_graph` и `trace_path` продолжают возвращать полный QN
  каждой перегрузки.

Полный набор `c_lsp` завершился как `760 passed`. Итоговый ограниченный прогон
наборов `fqn`, `watcher`, `store_checkpoint`, `registry`, `extraction`, `c_lsp`,
`pipeline`, `parallel`, `incremental`, `cross_repo`, `mcp` и `store_search`
завершился с кодом `0`:
`2031 passed, 6 skipped`. Рабочий бинарник также собран с кодом `0`.

## Вне границ доработки

- Отдельное сохраняемое поле `symbol_id`.
- Идентичность перегрузки, зависящая от возвращаемого типа или `noexcept`.
- Манглинг ABI средствами компилятора и совместимость ABI между разными
  цепочками инструментов.
- Семантическое сведение псевдонимов и разных эквивалентных написаний типа к
  одному компиляторному типу.
- Возврат отброшенной реализации блокировок `persistence` из прежних доработок
  форка.

поведению MCP из апстрима `v0.10.8` нужно отменить изменения реализации, а после
оформления переноса коммитом — отменить соответствующий коммит. При переходе
между прежним и новым форматами идентичности требуется полная переиндексация.
