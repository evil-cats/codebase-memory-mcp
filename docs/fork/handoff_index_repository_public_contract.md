# Сужение публичного контракта `index_repository`

Статус: реализована и функционально проверена.
Дата: 2026-08-03.
Ветка: `v0.9.1-rc.1-lora`.
База апстрима: `v0.9.1-rc.1`
(`ee9833df2c72b750378273897ffec9410fc2c4f2`).

## Назначение

Упростить публикуемый MCP-контракт `index_repository`: оставить клиенту выбор
репозитория и режима индексации, но не предлагать через описание инструмента
ручное имя проекта и создание переносимого артефакта.

Доработка удаляет параметры `name` и `persistence` из `inputSchema` и всех
относящихся к инструменту пользовательских описаний.

## Исходное поведение

До доработки ответ `tools/list` публиковал для `index_repository` следующие
свойства:

```text
repo_path
mode
target_projects
name
persistence
```

`repo_path` является обязательным. Остальные свойства необязательны.

Описание `name` обещало клиенту возможность переопределить автоматически
вычисленное имя проекта и объясняло нормализацию небезопасных символов.
Описание `persistence` предлагало записать переносимый артефакт
`.codebase-memory/graph.db.zst`.

Эти два параметра попадали в контракт, который MCP-клиент показывает модели.
В частности, они присутствовали в сформированной сигнатуре вызываемого
инструмента и поэтому выглядели как рекомендуемые пользовательские возможности.

## Требуемый публичный контракт

После доработки раздел `inputSchema.properties` должен содержать только три
свойства:

```text
repo_path
mode
target_projects
```

Существующие типы, значения `enum`, значение по умолчанию и тексты
`description` этих свойств сохраняются без изменений. В массиве `required`
остаётся только `repo_path`. Описание самого инструмента также сохраняется, за
исключением относящихся к удалённым параметрам формулировок, если они появятся в
текущей реализации.

Из опубликованных метаданных должны исчезнуть:

- свойство `name` и описание переопределения имени проекта;
- свойство `persistence` и описание записи
  `.codebase-memory/graph.db.zst`;
- любые иные формулировки в описании `index_repository`, которые предлагают
  клиенту передать эти параметры.

Удаление не должно затронуть описание режимов, отчёт о полноте индексации,
назначение `target_projects` и рекомендацию сначала обновить индексы целевых
проектов.

## Имя проекта без `name`

Для вызова по опубликованному контракту имя проекта всегда выводится сервером из
канонического `repo_path` через существующий `cbm_project_name_from_path()`.
Алгоритм вычисления имени, его нормализация и ограничение длины этой доработкой
не меняются.

Следовательно, обычный MCP-клиент больше не выбирает ключ проекта независимо от
пути. Для обращения к созданному индексу клиент использует имя, которое вернул
`index_repository` или `list_projects`.

## Поведение без `persistence`

Обычный вызов через опубликованную схему больше не предлагает создавать или
обновлять `.codebase-memory/graph.db.zst`. При отсутствии аргумента сохраняется
текущее значение по умолчанию `false`.

Подсистема импорта и экспорта артефактов, внутренний флаг конвейера и относящиеся
к ним тесты этой доработкой не удаляются.

## Граница совместимости

Доработка изменяет поверхность обнаружения MCP, которую сервер возвращает через
`tools/list`. Она не требует удалять разбор `name` и `persistence` из обработчика
`index_repository` и координатора демона.

Это сохраняет совместимость с уже существующими прямыми JSON-RPC-вызовами и
внутренними путями выполнения, но новые клиенты, строящие вызов по `inputSchema`,
больше не увидят эти параметры. Жёсткое отклонение скрытых или неизвестных полей
через `additionalProperties: false` в границы этой карточки не входит.

## Реализация

- В `src/mcp/mcp.c` из `TOOLS[].input_schema` для `index_repository` удалены
  свойства `name` и `persistence` вместе с их описаниями. Остальные свойства,
  обязательность `repo_path` и описание самого инструмента не изменены.
- Обработчик `index_repository`, координация демона и поддержка переносимого
  артефакта не менялись. Прямые JSON-RPC-вызовы со скрытыми параметрами
  продолжают разбираться прежним кодом.
- В `tests/test_mcp.c` прежняя проверка публикации `name` заменена тестом
  `mcp_index_repository_hides_internal_options`. Тест структурно разбирает
  фактический результат `cbm_mcp_tools_list()` и проверяет ключевые свойства
  сохранённого публичного контракта, а не отдельные подстроки JSON.

## Обязательные регрессионные проверки

Тест должен получить фактическое содержимое ответа `tools/list` через
`cbm_mcp_tools_list()`, структурно найти `index_repository` и проверить
следующее:

1. В `inputSchema.properties` отсутствует `name`.
2. В `inputSchema.properties` отсутствует `persistence`.
3. `repo_path` остаётся строковым и обязательным свойством.
4. `mode` сохраняет четыре текущих значения и значение по умолчанию `full`.
5. `target_projects` остаётся массивом строк.
6. В `description` инструмента и сохранённых описаниях его схемы нет обещаний
   передать ручное имя проекта или включить экспорт артефакта.
7. Остальные инструменты и их схемы не меняются.

Для проверки реализации используются:

```bash
make -f Makefile.cbm build/c/test-runner
build/c/test-runner mcp
make -f Makefile.cbm lint-format
git diff --check
```

Для карточки отдельно выполнить проектный Markdown-lint или, при отсутствии
локальной команды и конфигурации, `markdownlint-cli2` с принятой резервной
конфигурацией.

## Выполненная проверка

- До изменения схемы новый регрессионный тест завершился ожидаемой ошибкой:
  вместо трёх публичных свойств он обнаружил пять.
- После изменения схемы набор `mcp`: `180 passed, 2 skipped`.
- `make -f Makefile.cbm lint-format` и `git diff --check` проходят.
- `markdownlint-cli2` с принятой конфигурацией для этой карточки проходит.

При прогоне с ASan и UBSan сохранилась не относящаяся к этой доработке
UBSan-диагностика в `src/pipeline/pass_similarity.c:152`. Она возникает в другом
индексаторном тесте; набор `mcp` завершается с кодом `0`.

## Критерии готовности

- Фактический ответ `tools/list` для `index_repository` не содержит свойств
  `name` и `persistence`.
- Сформированная по этой схеме сигнатура инструмента также не содержит этих
  параметров и их описаний.
- `repo_path`, `mode` и `target_projects` сохраняют прежний контракт.
- Автоматическое вычисление имени проекта по `repo_path` продолжает работать.
- Индексация в режимах `full`, `moderate`, `fast` и
  `cross-repo-intelligence` не меняет поведение.
- Связанный набор тестов MCP и проверки форматирования проходят.

## Вне границ доработки

- Изменение алгоритма `cbm_project_name_from_path()`.
- Удаление `cbm_pipeline_set_project_name()` или внутренних вызовов с явным
  именем проекта.
- Удаление поддержки `.codebase-memory/graph.db.zst` из конвейера, CLI или
  внутренних API.
- Запрет прежних параметров в прямом JSON-RPC-запросе.
- Изменение режимов индексации, `target_projects`, отчёта о полноте или формата
  результата `index_repository`.
- Изменение описаний других MCP-инструментов.

## Восстановление после обновления upstream

При следующем обновлении upstream сначала проверить фактический ответ
`tools/list`. Если `name` и `persistence` уже удалены из публичной схемы и
описаний, переносить эту правку повторно не нужно. В противном случае следует
восстановить новый публичный контракт, не удаляя внутренние механизмы только
из-за совпадения их имён с ранее опубликованными параметрами.

## Откат

Для отката вернуть свойства `name` и `persistence` с их прежними описаниями в
`TOOLS[].input_schema` и восстановить прежнюю проверку `tools/list`. Внутренний
обработчик при таком откате менять не требуется, поскольку эта карточка его не
удаляет.
