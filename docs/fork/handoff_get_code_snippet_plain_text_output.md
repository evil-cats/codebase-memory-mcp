# Компактный текстовый ответ `get_code_snippet`

Статус: реализовано и локально проверено в рабочем дереве.
Дата согласования: 2026-09-06.
Дата реализации: 2026-09-06.
Ветка: `v0.10.8-lora`.
Коммит ветки на момент согласования:
`4e19f14894b09743e04ea4b8caacbcbd3221d0d2`.

## Назначение

Изменить публичный контракт `get_code_snippet`, чтобы модель получала исходный
код как обычный текст, а не как JSON-строку с экранированными переводами строк
и кавычками.

Карточка предназначена для агента без контекста исходного разговора. Она
фиксирует согласованный формат, границу размера, область реализации и
обязательные проверки.

## Проблема

До этой доработки `build_snippet_response()` собирал JSON-объект, сериализовал
его в строку и передавал эту строку через `cbm_mcp_text_result()`. Поле `source`
поэтому попадало в контекст модели с последовательностями `\n`, `\"` и
дополнительной JSON-структурой.

Это не ограничение MCP: `content[].text` может содержать обычный многострочный
текст. JSON внутри текстового результата является лишним уровнем кодирования.

Кроме исходника прежний ответ содержал сведения о графовых соседях. Они
дублировали `trace_path`, который возвращает более полный графовый результат с
точными `qualified_name`, направлением, глубиной и пагинацией.

## Согласованный вход

У `get_code_snippet` остаются только два аргумента:

- `project` — обязательное имя индексированного проекта;
- `qualified_name` — обязательный идентификатор символа.

Аргумент `include_neighbors` удаляется. Аргумент `format` не добавляется.
Успешный ответ всегда имеет один текстовый формат.

Существующие правила разрешения символа по точному `qualified_name`, уникальному
короткому имени и однозначному суффиксу не меняются. Неоднозначность, отсутствие
символа и невозможность прочитать исходник должны возвращаться как MCP-ошибки,
а не как успешный ответ с JSON или заглушкой вместо кода.

## Ответ с исходным кодом

Если полный исходник проходит ограничение размера, ответ имеет точную форму:

```text
qn: tests.test_mcp.call_snippet
path: tests/test_mcp.c
lines: 8939,8944

static char *call_snippet(cbm_mcp_server_t *srv, const char *args_json) {
    char *raw = cbm_mcp_handle_tool(srv, "get_code_snippet", args_json);
    char *text = extract_text_content(raw);
    free(raw);
    return text;
}
```

Требования к полям и исходнику:

- `qn` содержит разрешённый полный `qualified_name`;
- `path` содержит путь относительно корня проекта, без абсолютного префикса;
- `lines` содержит полный нормализованный диапазон символа в форме
  `<start>,<end>`;
- после `lines` находится одна пустая строка;
- далее до конца ответа расположен дословный исходник;
- исходник не заключается в Markdown-fence, не получает дополнительных
  отступов или номеров строк и не проходит JSON-экранирование;
- если исходный текст заканчивается переводом строки, он сохраняется.

Поскольку исходник завершает ответ, строки кода, похожие на метаданные, не
создают неоднозначности для следующих полей: полей после исходника нет.

## Ответ при превышении размера

Размер оценивается по UTF-8-тексту исходника после применения существующей
санитизации с заменой невалидных байтов:

```text
estimated_tokens = size / 4
```

Здесь `size` — число байт, а деление является целочисленным. Если
`estimated_tokens > 9000`, исходник не возвращается даже частично:

```text
qn: tests.test_mcp.call_snippet
path: tests/test_mcp.c
lines: 8939,8944
output_truncated: true
```

Таким образом, максимальный размер возвращаемого исходника равен `36003`
байтам после UTF-8-санитизации. При превышении порога вызывающая модель получает
полный диапазон и может прочитать файл частями отдельным файловым инструментом.

Прежний лимит `MCP_SNIPPET_MAX_LINES` и выдача первых 500 строк удалены.
`get_code_snippet` больше никогда не возвращает частичный исходник: либо весь
код символа, либо только метаданные с `output_truncated: true`.

## Удаляемые поля

В успешном ответе больше не возвращаются:

- `name` и `label`;
- `start_line` и `end_line` как отдельные JSON-поля;
- `source`, `source_clipped` и `clipped_at_lines` как JSON-поля;
- `match_method`;
- `callers`, `callees`, `caller_names` и `callee_names`;
- `alternatives`;
- `coverage_note`.

Диапазон не теряется: он переходит в строку `lines`. Графовые связи необходимо
получать через `trace_path` или `query_graph`. Предупреждение о частичном
покрытии индекса не относится к дословно прочитанному исходнику и не должно
засорять результат этого инструмента.

## Описание инструмента для агента

Регистрация `get_code_snippet` в `src/mcp/mcp.c` является публичным описанием,
которое получает агент. Её необходимо обновить одновременно с реализацией.

Новое описание должно явно сообщать:

- перед вызовом следует найти точный `qualified_name` через `search_graph`;
- ответ содержит `qn`, относительный `path`, диапазон `lines` и затем дословный
  исходник;
- при оценке свыше 9000 токенов код не возвращается и устанавливается
  `output_truncated: true`;
- полный код в этом случае следует читать частями по возвращённым координатам;
- графовые связи следует получать через `trace_path`, а не через
  `get_code_snippet`.

JSON Schema инструмента должна перечислять только `project` и
`qualified_name`; оба поля обязательны.

## Требуемая реализация

Основная область изменения:

- `src/mcp/mcp.c`:
  - обновить описание и JSON Schema инструмента;
  - удалить разбор `include_neighbors`;
  - заменить JSON-сборку успешного ответа на компактную текстовую сборку;
  - возвращать относительный `node->file_path` как `path`;
  - удалить чтение только первых 500 строк;
  - проверить полный текст по согласованной оценке размера;
  - сделать невозможность чтения исходника MCP-ошибкой;
  - не менять формат ответов других MCP-инструментов;
- `tests/test_mcp.c`:
  - переписать проверки `get_code_snippet` на наблюдаемый текстовый контракт;
  - удалить сценарии соседей;
  - заменить регрессию частичного чтения проверкой полного отказа от исходника
    при превышении порога;
  - проверить относительный путь, форму диапазона и отсутствие JSON-экранирования;
  - сохранить регрессию точного однострочного диапазона;
  - проверить ошибку чтения исходника и неоднозначное разрешение.

Общую функцию графовых соседей в store удалять нельзя: она используется
другими инструментами. Общий JSON-ответ `snippet_suggestions()` также нельзя
механически менять, если это изменит `trace_call_path`; для
`get_code_snippet` нужен локальный error-path.

## Совместимость и предшествующие карточки

Это намеренное изменение публичного ответа `get_code_snippet`. Режим
совместимости с прежним JSON не сохраняется.

Карточки
`handoff_get_code_snippet_preserve_symbol_range_when_clipped.md` и
`handoff_get_code_snippet_single_line_range.md` остаются историей предыдущих
исправлений. Новый контракт сохраняет их важное свойство — точный полный
диапазон символа, — но заменяет прежнюю выдачу первых 500 строк правилом «весь
исходник или никакого исходника».

Не меняются:

- извлечение и хранение координат символов;
- формирование `qualified_name`;
- порядок разрешения точного, короткого и суффиксного имени;
- `search_graph`, `trace_path`, `query_graph` и их форматы;
- оболочка JSON-RPC протокола MCP.

## Результат реализации

Изменения выполнены в рабочем дереве поверх указанного выше коммита:

- регистрация `get_code_snippet` публикует новую схему и описание;
- успешный ответ собирается как обычный текст с относительным путём;
- чтение ограничено согласованным бюджетом без выдачи частичного буфера;
- неоднозначность и недоступный исходник возвращаются как MCP-ошибки;
- тесты закрепляют точный ответ, длинную физическую строку, обе стороны границы
  размера, санитизацию, разрешение имён и ошибки.

Локальная сборка завершилась успешно. Целевой набор `mcp` прошёл с результатом
`210 passed, 6 skipped`.

Минимальный обязательный проход:

```bash
make -f Makefile.cbm build/c/test-runner
build/c/test-runner mcp
make -f Makefile.cbm lint-format

```

Для карточки при отсутствии локальной конфигурации Markdown-lint:

```bash
markdownlint-cli2 --config /home/slader/.codex/.markdownlint-cli2.yaml \
    docs/fork/handoff_get_code_snippet_plain_text_output.md
```

Кроме автоматических проверок необходимо вручную проверить ответы для:

1. обычного многострочного символа;
2. однострочного символа;
3. однострочного символа длиннее внутреннего буфера чтения;
4. исходника размером ровно на допустимой границе;
5. исходника, превышающего границу;
6. невалидного UTF-8, который после санитизации превышает границу;
7. неоднозначного короткого имени;
8. отсутствующего или недоступного исходного файла.

## Критерии готовности

- Описание инструмента и JSON Schema соответствуют новому контракту.
- Успешный ответ содержит только `qn`, относительный `path`, `lines` и полный
  дословный исходник.
- Ответ сверх лимита содержит только те же метаданные и
  `output_truncated: true`.
- Частичный исходник не возвращается ни при каких размерах символа.
- `include_neighbors`, альтернативные форматы и графовые поля удалены из
  `get_code_snippet`.
- Ошибки разрешения и чтения не маскируются успешным ответом.
- Целевой набор `mcp`, форматирование, `git diff --check` и Markdown-lint
  проходят.
- Карточка и изменённые комментарии прошли русскую редакторскую вычитку.

## Вне области изменения

- Изменение алгоритма построения `qualified_name`.
- Добавление диапазона, курсора, пагинации или выбора формата во входные
  параметры `get_code_snippet`.
- Автоматическое чтение следующих частей большого символа.
- Изменение токенизатора модели или попытка точно воспроизвести его подсчёт.
- Рефакторинг графовых обходов и соседних MCP-инструментов.
